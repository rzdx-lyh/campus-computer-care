# 校园电脑故障知识库 · Campus PC Fault KB

> 把宿舍里那些「重启一下就好」和「千万别乱动」的故障经验，变成 AI 能读懂的结构化知识。

## 项目简介

宿舍里的电脑故障，每个学生都遇到过：开不了机、蓝屏、连不上校园网、风扇狂转。第一反应是群里问、网上搜，答案零散甚至误导，轻则耽误交作业，重则丢失论文数据；学校报修又要等一两天。

本项目把一线排障经验整理成结构化知识库，用「故障类型—现象关键词—追问问题—可能原因—排查步骤—紧急程度」六个字段描述每条故障，覆盖开机异常、蓝屏、Wi-Fi、校园网认证、散热、键盘、电池、卡顿、闪退、花屏十大场景，共 25 条高频条目。

在知识库之上，系统用大模型做三件事：把口语描述映射到标准条目，像老技术员一样追问、补齐信息，再生成个性化排查步骤；一旦识别到数据风险，优先提醒备份并转人工。知识库与模型解耦，条目可增删、可版本化，换模型不换知识。

目标很朴素：做宿舍里的「第一响应人」，把常见故障拦在报修之前，让真正需要维修的问题更快送到人手里。

## 知识库结构

每条故障是一个六元组，字段设计直接对应「听懂问题 → 问清细节 → 给出动作」的诊断链路：

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| `故障类型` | 检索与统计的分类主键 | `蓝屏` |
| `现象关键词` | 学生口语到标准条目的映射入口 | `["开不了机", "按电源没反应"]` |
| `追问问题` | 补全诊断所需的关键信息 | `["电源灯亮不亮？"]` |
| `可能原因` | 按概率排序的原因假设 | `["电源适配器故障"]` |
| `排查步骤` | 可执行、有先后顺序的动作 | `["长按电源键 20 秒放电"]` |
| `紧急程度` | 决定提示语气与是否转人工 | `高` / `中` |

## 覆盖范围

| 故障类型 | 条目数 | 典型现象 |
| --- | ---: | --- |
| 开机异常 | 3 | 按电源无反应、通电黑屏、找不到启动盘 |
| 蓝屏 | 4 | `0x0000007B`、显卡 TDR、内存报错、更新后无限修复 |
| WiFi连不上 | 3 | 搜不到 SSID、连上无 Internet、频繁掉线 |
| 校园网认证失败 | 3 | 认证页打不开、账号/设备数超限、认证后仍无网 |
| 风扇噪音 | 2 | 开机狂转异响、高负载过热降频 |
| 键盘失灵 | 2 | 部分按键失灵、整块键盘无响应 |
| 电池不耐用 | 2 | 续航衰减跳电、插电不充电 |
| 系统卡顿 | 2 | 开机慢/C 盘爆满、CPU 与内存占满 |
| 软件闪退 | 2 | 常用软件闪退、专业软件缺运行库 |
| 显示器花屏 | 2 | 内屏条纹闪烁、外接屏花屏无信号 |

合计 **25 条**、125 个现象关键词、150 条排查步骤，其中 8 条标记为「高」紧急程度（涉及数据丢失、硬件损坏或安全隐患）。

## 快速使用

```python
import json

with open("data/knowledge_base.json", encoding="utf-8") as f:
    kb = json.load(f)

query = "电脑开机风扇转但是屏幕黑的"
hits = [
    item for item in kb
    if any(kw in query for kw in item["现象关键词"])
]
print(hits[0]["追问问题"])   # 交给大模型继续追问
```

也可以直接作为 RAG 的语料源：按 `故障类型` 或关键词召回 1–3 条，再把 `追问问题`、`可能原因`、`排查步骤` 注入提示词。

## 说明

- 排查步骤面向「有基本动手能力的学生」，涉及拆机、主板、电池鼓包的操作一律建议送修。
- 条目可按学校实际网络环境（SSID、认证方式、报修流程）替换字段内容，结构不变。
- 欢迎提交 Issue 补充新故障，或按同一 schema 提交 PR。
