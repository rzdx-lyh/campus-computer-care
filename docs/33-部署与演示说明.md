> 用途：把「校园电脑管家」以生产模式跑起来，供评委/同学访问；包含本地、临时公网隧道、Vercel 三种方式。

## 1. 本地生产模式（最稳，答辩兜底）

```bash
cd "C:\Users\Administrator\Desktop\code\ai web\ai web\chat"
npm ci
npm run build
npm start            # 默认 http://localhost:3000
```

本机当前生产实例跑在 **http://127.0.0.1:3107**（端口 3107，避免与开发服务器冲突）。

环境变量（`.env.local`，不要提交）：

```bash
DEEPSEEK_API_KEY=your_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_WEB_SEARCH=false     # 演示默认关闭，减少延迟与无关证据
```

## 2. 临时公网演示（当前使用）

用 SSH 反向隧道把本机 3107 端口映射到公网：

```bash
ssh -o StrictHostKeyChecking=no -R 80:localhost:3107 nokey@localhost.run
```

- 启动后会打印形如 `https://xxxx.lhr.life` 的地址；本次为 `https://05446974de5f09.lhr.life`。
- **隧道进程一旦停止或网络断开，地址立即失效**；只适合临时演示，不适合长期提交。
- 已验证：`/`、`/graph`、`/diagnosis`、`/manifest.webmanifest`、`/sw.js` 均可访问。

### 安全注意（重要）

- 公网地址暴露了 `/api/diagnose`、`/api/repair-advice`、`/api/insight`，任何人都可能调用并消耗 DeepSeek 额度。
- 建议只在演示/评委访问期间开启，演示结束立即 `Ctrl+C` 停止隧道。
- 不要把 `.env.local`、Key、`.next`、`node_modules` 打包进提交物。

## 3. Vercel 正式部署（推荐用于长期在线演示）

前置：需要一个 Vercel 账号（本机当前未登录 CLI）。

```bash
cd "C:\Users\Administrator\Desktop\code\ai web\ai web\chat"
npx vercel login          # 浏览器/GitHub 登录
npx vercel --prod         # 按提示创建项目，Framework 选 Next.js
```

部署后在 Vercel 项目 **Settings → Environment Variables** 添加：

| 变量 | 值 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 你的 Key（不写进仓库） |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | `deepseek-flash` |
| `DEEPSEEK_WEB_SEARCH` | `false` |

然后在 **Deployments → Redeploy** 使环境变量生效。

> 赛事要求「在线演示」为可选加分项；如果时间不够，优先保证本地生产模式 + 演示视频，不要为了部署牺牲 PDF/视频。

## 4. PWA 安装与离线验证

- 生产模式（HTTPS 或 localhost）打开站点，浏览器地址栏出现安装图标，可「安装校园电脑管家」。
- 首次访问后 Service Worker 预缓存 `/`、`/graph`、`/diagnosis`、`/checkup`、manifest、offline 页面与图标。
- 断网刷新 `/graph`：应显示「故障知识图谱」与「离线 · 25 条故障可离线查看」。
- 修改前端资源后需要递增 `public/sw.js` 的 `CACHE_NAME`，否则旧缓存可能延迟生效。
