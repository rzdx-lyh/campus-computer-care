## 镜头 1：痛点与首页（0:00–1:00）

### 屏幕动作

- 黑底标题卡：`校园电脑管家 / 学生电脑 AI 诊断与报修`。
- 切换到宿舍电脑故障照片或首页全景。
- 鼠标依次指向“电脑体检”“AI 诊断”“知识图谱”。
- 顶部角色下拉框展示学生/维修员/管理员，但不切换。

### 逐字稿

“大家好，我们的作品是校园电脑管家。它解决的是宿舍里最常见的电脑问题：蓝屏、黑屏、断网、风扇异响。学生往往只能说出表面现象，网上的答案零散甚至过期，学校报修又需要重复描述。

所以我们把设备体检、多轮 AI 问诊、本地知识库、联网检索、报修工单和维修管理做成了一个闭环。

首页提供两个核心入口：电脑体检和 AI 诊断。顶部可以在学生、维修员和管理员之间切换，不同角色会看到不同导航和不同 AI 输出视角。”

## 镜头 2：设备体检（1:00–1:40）

### 屏幕动作

- 点击“开始电脑体检”。
- 展示设备内存、CPU 核心、网络连接、电池状态。
- 指向“已读取/不支持”状态和隐私说明。
- 点击“重新检测”。

### 逐字稿

“进入设备体检页，系统读取浏览器公开的设备能力，包括内存、CPU 逻辑核心、网络类型、延迟和电池状态。

这里有一个重要原则：浏览器不开放的字段，我们明确显示为不支持，而不是把它误判成硬件故障。所有设备信息只在本地读取，不上传服务器。

体检结果用于给学生一个基础判断，但真正定位问题，还需要继续描述故障。”

## 镜头 3：多轮诊断、RAG 证据、学习模式与错误码（1:40–3:30）

### 屏幕动作

- 进入 `/diagnosis`。
- 输入错误码：`0x0000007B INACCESSIBLE_BOOT_DEVICE`，展示错误码识别提示。
- 发送问题。
- 展示流式输出、结构化卡片、知识库来源、可能原因、步骤。
- 点击“一步一步教我”开关。
- 展示步骤 1/N、上一步、下一步。
- 点击“回答这个问题”，展示输入框预填。
- 展示“导出诊断报告”按钮。

### 逐字稿

“现在进入 AI 诊断。我们直接粘贴蓝屏错误码：0x0000007B 和 INACCESSIBLE_BOOT_DEVICE。

前端会自动识别错误码，并从知识库现象关键词生成映射，显示对应的故障类型。识别结果会作为上下文一起发给后端。

AI 首先进行多轮问诊。信息不足时，它会提出一到三个追问；前端保留最近对话，因此不会重复询问已经回答过的信息。

诊断结果不是一段不可验证的长文本，而是结构化 JSON。卡片展示故障摘要、风险等级、可能原因和建议步骤，同时列出本地知识库或联网来源、匹配关键词和置信度。这就是我们的 RAG 证据链。

对于学生，我们还提供学习模式。开启后，追问会变成步骤 1/N，用户可以上一步、下一步，并逐个回答问题，降低一次性理解多个问题的负担。

最后可以导出 Markdown 诊断报告，也可以直接生成报修工单。”

## 镜头 4：一键工单、维修闭环、评价与管理看板（3:30–5:20）

### 屏幕动作

- 点击“用诊断结果创建维修工单”。
- 工单页展示已带入的标题、设备、描述、优先级。
- 补充宿舍和预约时间，提交。
- 打开 `/tickets`，展示状态。
- 切换维修员角色，进入 `/technician`。
- 点击“AI 维修建议”，展示摘要、备件、工时、验收步骤。
- 点击填入维修记录，标记完成。
- 切换学生角色，在已完成工单中提交 1–5 星和一句话评价。
- 切换管理员，展示统计、平均评分、AI 洞察，点击“导出工单 CSV”。

### 逐字稿

“诊断结果可以一键带入工单。标题、设备类型、故障描述和优先级已经自动填好，学生只需要补充宿舍和预约时间。

工单状态从待接单、维修中到已完成。维修员进入工作台后，可以请求 AI 维修建议。建议包含可能原因、建议备件、预计工时和验收步骤，并且可以一键写入维修记录。

完成维修后，学生可以给出 1 到 5 星和一句话评价。工单列表、维修员工作台和管理员看板都会汇总平均评分与评价数量。

管理员还可以生成 AI 运维洞察，并导出带 UTF-8 BOM 的 CSV，Excel 打开中文不会乱码。”

## 镜头 5：PWA、降级、工程质量与总结（5:20–6:30）

### 屏幕动作

- 打开 `/graph`，展示 10 类故障、25 条知识、现象和原因节点。
- 点击一个节点，展示跳转诊断页并预填问题。
- 打开 DevTools 展示 Service Worker 已激活。
- Network 切到 Offline，刷新 `/graph`，展示“离线 · 25 条故障可离线查看”。
- 切回 Online。
- 打开终端展示 `npm test` 8 条通过、`npm run build` 通过。
- 展示 GitHub Actions 配置或 Git 提交历史。
- 回到首页，结束。

### 逐字稿

“除了诊断，我们还实现了纯 SVG 故障知识图谱，展示十类故障、二十五条知识、现象和原因节点。点击任意节点，会带着问题进入诊断页。

系统支持 PWA。生产环境会注册 Service Worker，缓存首页、诊断、体检和知识图谱。我们把网络切到 Offline，再刷新知识图谱，页面仍然可以打开，并提示二十五条故障可离线查看。AI 和 API 仍然需要联网，这是明确的能力边界。

在工程质量方面，我们使用 TypeScript 严格类型检查、八条核心自动化测试、GitHub Actions 持续集成，并保留按模块划分的 Git 提交历史。

最后总结一下：校园电脑管家的价值，不是让 AI 替代维修员，而是把常见故障拦在报修之前，把真正需要维修的问题更快、更准确地送到维修员手里。

谢谢大家。”

## 录制注意事项

1. 所有 API Key、浏览器账号、宿舍个人信息必须打码或避免出现。
2. 字幕不要遮挡错误码、来源链接和状态按钮。
3. 镜头 3 和镜头 5 的加载过程可适度加速，但不要剪掉关键结果。
4. 最终导出 1080p MP4，文件建议控制在 300 MB 以内。
5. 视频、PDF、仓库链接须在答辩前重新验证可访问。
